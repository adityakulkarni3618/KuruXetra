# KURUXETRA SPORTS MANAGEMENT SYSTEM (KSMS) - PROJECT DIGEST
===========================================================

## Project Stack
- **Backend**: Node.js, Express, TypeScript, PostgreSQL, Prisma, JWT authentication.
- **Frontend**: Next.js 15 (App Router), TypeScript, Tailwind CSS, Recharts.

---

## Directory Structure
- `/backend`
  - `src/index.ts`: Express server entrypoint, API routing, CORS, JSON body parsing, health check.
  - `src/routes/`: API router modules for auth, sports, attendance, workouts, running, leaderboard, users, admin.
  - `prisma/`
    - `schema.prisma`: Core database schema.
    - `seed.ts`: Seed script for Super Admin and demo sports.
  - `package.json`: Backend scripts (`dev`, `build`, `start`, `prisma:generate`, `prisma:migrate`, `prisma:seed`).
- `/frontend`
  - `app/`: Next.js App Router with login, register, dashboard, and nested dashboard pages.
  - `app/dashboard/`: Protected dashboard area with admin, attendance, captain, leaderboard, running, sports, and workouts views.
  - `components/`: UI components used by frontend pages.
  - `lib/`: Shared frontend helpers including `api.ts` and `auth-context.tsx`.
  - `package.json`: Frontend scripts (`dev`, `build`, `start`, `lint`).

---

## Backend Details
- Uses `tsx watch src/index.ts` for local development.
- Backend listens on port `4000` by default and exposes `/health`.
- CORS origin uses `process.env.CORS_ORIGIN` or defaults to `http://localhost:3000`.
- Primary API routes:
  - `POST /api/auth/*`
  - `GET/POST /api/sports/*`
  - `GET/POST /api/attendance/*`
  - `GET/POST /api/workouts/*`
  - `GET/POST /api/running/*`
  - `GET /api/leaderboard/*`
  - `GET/POST /api/users/*`
  - `GET/POST /api/admin/*`

## Core Database Schema (Prisma)
- **Role Enum**: `SUPER_ADMIN`, `CAPTAIN`, `STUDENT_ATHLETE`, `FITNESS_MEMBER`
- **UserStatus Enum**: `PENDING_APPROVAL`, `ACTIVE`, `SUSPENDED`
- **MembershipStatus Enum**: `PENDING`, `APPROVED`, `REJECTED`, `REMOVED`
- **Models**:
  - `Season`: Tracks sports seasons and optionally links memberships, attendance, workouts, runs, and points.
  - `User`: Stores user identity, academic details, contact info, role, status, and related activity records.
  - `Sport`: Stores sport metadata, captain relation, practice info, capacity, and status.
  - `Membership`: Joins a user to a sport with approval status and optional season.
  - `Attendance`: Stores check-in/out, duration, sport, season, and marking source.
  - `Workout`: Records exercise entries, sets, reps, weight, duration, calories, heart rate, notes, and optional photo URL.
  - `RunningLog`: Records distance, duration, pace, speed, calories, and notes.
  - `PointsLedger`: Append-only points ledger with reason and optional reference ID.

## Key Terminal Commands

### Database Startup (Docker)
```bash
docker run --name ksms-db -e POSTGRES_USER=ksms_user -e POSTGRES_PASSWORD=ksms_pass -e POSTGRES_DB=ksms -p 5432:5432 -d postgres:16
```

### Backend Setup & Running
```bash
cd backend
npm install
cp .env.example .env     # then update DATABASE_URL, JWT_SECRET, CORS_ORIGIN as needed
npx prisma generate
npx prisma migrate dev --name init
npx prisma db seed
npm run dev              # starts backend on http://localhost:4000
```

### Frontend Setup & Running
```bash
cd frontend
npm install
echo "NEXT_PUBLIC_API_URL=http://localhost:4000" > .env.local
npm run dev              # starts frontend on http://localhost:3000
```
